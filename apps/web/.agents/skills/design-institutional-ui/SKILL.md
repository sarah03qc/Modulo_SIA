# Diseño institucional de interfaces

1. Lee `AGENTS.md`, `docs/institutional/DESIGN_ACCESSIBILITY_SPEC.md` y el requerimiento vigente. Anota rol, tarea, contexto territorial, decisiones profesionales y acciones autorizadas. Marca conflictos de fuentes como `NEEDS_VALIDATION`.
2. Representa el recorrido actual en tres a cinco pasos. Identifica dónde se pierde contexto, se repite una acción o se vuelve ambigua una decisión. Distingue evidencia de hipótesis.
3. Elige una dirección visual concreta. Define qué se lee primero, qué acción merece énfasis y qué se agrupa. Usa Arial, activos oficiales y colores institucionales con contraste comprobado.
4. Elige un patrón en [Patrones por tarea](references/patrones.md). Define carga, vacío, error y éxito. Conserva campos, términos y acciones aprobados.
5. Entrega ruta, rol, tarea, jerarquía, patrón y criterios verificables. Si hay implementación autorizada, revisa el render y solicita revisión independiente de A-08 con `audit-rendered-ui`.

Para gráficos abre también `design-reporting-visuals`. Consulta [las fuentes y revisiones](../../../../../docs/agent-workflow/visual-ui.md).
